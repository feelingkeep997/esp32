## 0. 先建立正确认知（10 分钟，别跳过）

**这个项目是什么**
- 单体循环（super-loop）飞控固件，约 6570 行 C++，五层目录：`User/`(入口) `application/`(飞行逻辑) `Middlewares/`(公共库) `Bsp/`(板级/通信) `Drivers/`(外设)。
- 构建：ESP-IDF **v5.1.6**，`sdkconfig:220` → `CONFIG_IDF_TARGET="esp32"`（经典 ESP32，走 `Bsp/board_config.h:115-151` 的默认引脚分支）。
- 无 FreeRTOS 自建任务：`app_main()` 里一条主任务顺序跑 `loop()` 14 步（`User/main.cpp:105-124`），只有 httpd 和 esp_wifi/lwIP 是隐式任务。

**三个必须提前知道的"事实修正"**（否则会把力气花错地方）
1. `README.md:7-43` 的目录结构是**旧的**（写的是 `main/` + `components/...`），实际以 `CMakeLists.txt` 为准；`README.md:54-57` 还把 ACRO 标成"自稳"、STAB 标成"定高"，与代码不符（代码：ACRO=纯角速率，STAB=姿态自稳，ALTHOLD=定高，见 `application/control.cpp:83`）。
2. **串口遥控器（SBUS/CRSF）这条链路是断的**：`Drivers/rc.cpp` 的 `normalizeRC()` 只写 `rollChannel` 等（`rc.cpp:157-161`），而 `rollChannel` 只在 `application/parameters.cpp:153` 被当作 NVS 参数存取，从未进入 `controlRoll`。全工程只有两处真正写 `controlRoll`：`Bsp/web_rc.cpp:262`（网页遥控）和 `Middlewares/mavlink.cpp:160`（MAVLink MANUAL_CONTROL）。
3. `Bsp/espnow.cpp` 有 212 行完整实现，但**不在 `Bsp/CMakeLists.txt` 的 SRCS 里**，且 `ESPNOW_ENABLED` 宏无处定义 → 当前不参与编译。这正是"ESP-NOW-only 方案"的落点。

**读码方法（本工程专属捷径）**
每个 `.cpp` 头部都有固定五段中文注释：`职责 / 关键逻辑 / 输入输出 / 重要参数 / 边界情况与潜在风险`。
→ **永远先读文件头注释，再进函数**；它已经是作者留给你的地图。学完一个模块后，再回头读头注释，检验自己是否真的看懂了。

## 3. 阶段 2：感知——从 SPI 字节到姿态（2 天）

**读**（按数据流顺序）：
`Drivers/mpu9250.h` → `Drivers/mpu9250.cpp`(240) → `Drivers/imu.cpp`(257) → `Middlewares/vector.h`(173) → `Middlewares/quaternion.h`(261) → `Middlewares/lpf.h`(67) → `application/estimate.cpp`(125)

**先记住这些硬件锚点**（读代码时用来对照）
- WHO_AM_I 接受 **0x71/0x73（MPU9250/9255）或 0x70（MPU6500）**（`mpu9250.cpp:216`、`imu.cpp:124`）。**不支持 MPU6050（0x68，且 MPU6050 没有 SPI）** —— 平时口头叫"MPU6050"，写文档/答辩时要说 MPU9250 系。
- SPI：SCK=18 / MISO=19 / MOSI=23 / CS=5，**10MHz**，HSPI 主机（`board_config.h:127-130`、`mpu9250.cpp:51-78`）。
- 量程：gyro **±1000 dps**、acc **±16g**（`imu.cpp:116`）；`SMPLRT_DIV=7` → 内部 125Hz，DLPF `CONFIG=0x06` ≈ 21Hz（`mpu9250.cpp:193-208`）。灵敏度硬编码 2048 LSB/(°/s)、16384 或 2048 LSB/g 一类常量（`mpu9250.cpp:178-185`）——**改量程必须同时改这里**，否则角度会成比例错。
- 一次 burst 读 14 字节从 0x3B 起（`mpu9250.cpp:134-160`），gyro 在 buffer[8..13]（这里历史上踩过 off-by-one）。

**链路复述（能背下来就算过关）**
raw → `readIMU()`：每轴 `gyroBiasFilter*(0.01)` 低通 → 减 `gyroBias` → acc 减 `accBias` 乘 `accScale` → 按 `imuRotation` 旋转
→ `estimate()` 内部固定顺序：`applyGyro()`（去零偏+低通+四元数增量旋转）→ `applyAcc()`（**仅 `landed` 时**用重力方向以 `accWeight=0.003` 慢修）→ `applyLevel()`（默认 `levelWeight=0` 即关闭）→ `estimateVelZ()`（机体系→世界系、去重力、积分 + 泄漏 `ALT_VEL_LEAK=0.15`）。

**必答题**
1. `landed` 的判据是什么？为什么起飞瞬间和自由落体会误判？（`estimate.cpp:95`：电机不转 且 |acc| 在 1g±10%）
2. 为什么 `accWeight` 只有 0.003？为什么加速度计不在飞行中也参与修正？
3. 纯陀螺积分为什么会漂？本工程里哪两个机制抑制漂移、它们默认谁开着谁关着？
4. `ca` 校准加速度计（`imu.cpp` 的 `calibrateAccel`）做了什么、结果存到哪？`gyroBias` 谁负责校？（提示：`calibrateGyroOnce()` / `calibrateAccelOnce()` **没有任何调用者**，`gyroBias` 实际恒 0，参数表里也没有 `IMU_GYRO_BIAS_*` —— 这是**真实缺口**，见阶段 5 方向 B）
5. `imuOK=false` 的完整后果链是什么？（`readIMU` 提前 return → gyro/acc 变成陈旧值而非清零 → `interpretControls` 拒绝解锁，`control.cpp:140-146`）
6. `mpu9250_set_rotation()` 是空函数（`mpu9250.cpp:237-240`），真实旋转发生在 `readIMU` 里用 `Quaternion::conjugate(v)`（`quaternion.h:226`，即 q·v·q⁻¹）—— 所以 `IMU_ROT_*` 的语义是"安装四元数的共轭"，符号很容易弄反。自己验证一次：绕机体 X 正转，看 roll 是正还是负。

**动手实验（⚠️ 全程拆桨 / 不上电机动，见 §7 安全守则）**
1. **漂移量化**：静置 10 分钟，VOFA+ 记录通道 7-9（rad），换算成 °/min。这既是学习成果，也是论文里可用的实测数据。
2. **积分滞后**：手动慢转机体，对比通道 4-6（gyro deg/s）与 7-9（姿态）的相位差，直观理解"姿态是陀螺的积分"。
3. **滤波器手感**：`p EST_RATES_LPF_A 0.05`（原 0.2），对比噪声；再改回。热改参数立即生效，不用重编译。
4. **标定闭环**：敲 `ca`，前后各 `p IMU_ACC_BIAS_X`，确认值变了；断电重启再 `p`，确认 NVS 自动存了。

**产出物**：漂移曲线截图 + 一段"为什么这套估计会漂/何时修"的 200 字说明。

## 4. 阶段 3：控制——三个环与混控（3 天，毕设核心）

**读**：`application/control.cpp`(370，核心) → `Middlewares/pid.h`(87) → `application/motors.cpp`(157) → `docs/mixer-pid-sim.html`（本仓库自带的混控/PID 交互演示，可离线看直觉）

**控制链复述**
`control()` = `interpretControls()` → `interpretWebRC()` → `failsafe()` → `controlAttitude()` → `controlRates()` → `controlTorque()`（`control.cpp:117-126`），再由 `sendMotors()` 下发。
- 外环（姿态）：误差 = `rotationVectorBetween(upTarget, upActual)`，**只有 P**（`ROLL_P=6`，I/D=0），输出目标角速率，再叠 `ratesExtra` 前馈（偏航杆量直接进速率环，`control.cpp:184`）。
- 内环（角速率）：完整 PID（`0.06/0.1/0.001`，D 带 `alpha=0.2` 低通），输出力矩。
- 混控：X 型四轴 4 路线性组合 + `desaturate()` 等比压缩 + 钳位 [0,1]（`control.cpp:284-293`）。
- 偏航单独用 `wrapAngle` 处理 ±π 跳变（`control.cpp:254`）。

**必答题**
1. 五个模式（RAW/ACRO/STAB/ALTHOLD/AUTO）各自 `invalidate()` 了哪个目标量？为什么"置无效"比"加 if 分支"更干净？（`control.cpp:179-206`）
2. 姿态环为什么只有 P 就够了？加 I 会引入什么问题？
3. `controlAttitude`/`controlRates`/`controlTorque` 各自的跳过条件是什么（`!armed` / 目标无效 / `thrustTarget < motThrMin`）？这三道闸门保证了什么？
4. `desaturate()` 为什么保均值、压差量？代价是什么（大机动时总推力被压低 → 掉高度）？（`control.cpp:299-312`）
5. 电机下标语义：`MOTOR_*` 索引 **0=RL, 1=RR, 2=FR, 3=FL**，而 `BOARD_MOTOR_PINS {12,13,15,14}` 不是顺序排列（`motors.cpp:61-64` + `board_config.h:119`）→ 实际 RL=GPIO12、RR=13、FR=15、FL=14。手推一遍并把结论写进笔记；`cli.cpp:191` 的 `mot` 打印顺序也和下标不同，别被误导。⚠️ GPIO15 是 ESP32 的 strapping/启动引脚，用它驱动电机要确认不影响上电。
6. PWM 细节：LEDC_TIMER_0 + 低速模式 + `LEDC_AUTO_CLK`，通道 0..3 == 电机下标，**25kHz / 10bit**，`pwmMax=-1` ⇒ 走"纯占空比"分支 `duty=round(v*1023)`（`motors.cpp:54-58,80-127`）。想接标准 ESC 的 µs 模式，就把 `MOT_PWM_MAX` 设成 ≥0。
7. ALTHOLD：无气压计怎么"定高"？为什么松杆能收敛到悬停油门（`altHoldI=0.3` 在线学 `hoverThrustEst`）？为什么 >30s 后不可信？（`control.cpp:211-239` + `estimate.cpp:69-80`）

**动手**
- 无硬件：改 `docs/mixer-pid-sim.html` 里的力矩/推力，先在仿真里预测四路输出，再回代码验证你的符号约定对不对。
- 有硬件（**拆桨**）：网页遥控（AP `Drone_WiFi` / 密码 `12345678` → 打开 `http://192.168.4.1/`，控制台在 `/console`，遥控页在 `/web_rc`）解锁后轻推油门，同时用 `mot` 命令观察四路数值；再用 `mfr/mfl/mrr/mrl` 单独驱动每个电机，**核对是哪一个在转**（这一步能验证第 5 题的引脚映射，也是接错线唯一能被提前发现的时刻）。

**保护链（顺序即优先级，`safety.cpp:54-62`）**
`rcLossFailsafe`(1s) → `webRCLossFailsafe`(8s) → `autoFailsafe` → `invertedFailsafe`(cos<−0.7 持续 1.5s) → `batteryFailsafe`。
`descend()` 是**全工程唯一**把 `mode` 设成 `AUTO` 的地方：先复位 6 个 PID，把 `thrustTarget` 钳到 `ALTHOLD_HOVER_THRUST=0.7`，再按 `dt/descendTime(10s)` 线性减到 0 后 `armed=false`（`safety.cpp:79-100`）。

**参数系统**：注册表 `parameters[]`（`parameters.cpp:60-176`，含 `CTL_*`、`ALT_*`、`EST_*`、`IMU_*`、`MOT_*`、`SF_*`、`WIFI_*`/`MAV_*`），NVS 命名空间 **"flix"**，`syncParameters()` 只在 **1Hz 且不活跃时**写、只写变化项（`parameters.cpp:247-259`）。`preset` 会 `nvs_erase_all` + 重启，**连带抹掉 WiFi 凭证**。
两个易混点：`parameters.cpp:83` 把 `CTL_P_RATE_MAX` 映射到 `maxRate.y`（轴字母与 CTL_ 前缀刻意转置，别按字面理解）；`MOT_PIN_*`/`MOT_PWM_*` 带回调 `setupMotors`，改完立即重配外设。

**日志**：RAM 环形缓冲 `float logBuffer[LOG_SIZE][14]`（`log.cpp:65`），100Hz、时长 `BOARD_LOG_DURATION=8s`（≈44KB），**仅 `armed` 时记录**（`log.cpp:75`），列：`t, rates×3, ratesTarget×3, attitude×3(Euler), attitudeTarget×3, thrustTarget`，`log dump` 出 CSV。**没有 flash 落地**（`partitions.csv` 只有 nvs/otadata/phy/app）→ 想拿长日志必须自己加 data 分区或走串口。

**MAVLink 现状（毕设答辩可能被问到）**：手写 **v1** 帧（`0xFE`，无官方库）。发 HEARTBEAT(0)/EXTENDED_SYS_STATE(245) @2Hz，ATTITUDE_QUATERNION(31)/RC_CHANNELS_RAW(35)/ACTUATOR_CONTROL_TARGET(26)/SCALED_IMU(26)/SERIAL_CONTROL(126) @10Hz。
已知不兼容点：CRC 种子表对**未知 ID 返回 0**（`mavlink_compat.h:154-171`）而解析器会因 CRC 不符丢帧（`:219-232`）；ID 26 三重冲突且 `scaled_imu_pack` 硬编码 `msgid=26`；`LOG_DATA(120)` 等打包函数定义了但没调用 → **没有 MAVLink 日志下载**。这些解释了"为什么 QGC 里看不到完整数据"。

## 7. ⚠️ 安全守则（每次动手前读一遍）

1. **任何代码验证阶段，一律拆掉螺旋桨**。本工程有多条链路是"断的/半瘫的"，行为不完全可预测。
2. 首次电机测试用 `mfr/mfl/mrr/mrl`，短按、手指远离、注意 `pause()` 期间控制环停摆（`cli.cpp:98-111`）。
3. 上电前先 `p`/`sys` 看电量与堆；`disableBrownOut()` 关掉了欠压复位（`main.cpp:84`），电机启动掉压可能直接重启而非保护。
4. 想带桨试飞前，必须已经确认：电机顺序与桨转向一致（阶段 3 第 5 题）、混控符号正确、失控保护能触发（阶段 4 实验 3）。**目前固件还没有成功离地的确认记录**——把首飞当成一次有记录的实验，而不是必然事件。
5. 室内试飞、远离人；ALT_HOLD 的 `velZ` 只有几十秒可信（`estimate.cpp:53`）。
